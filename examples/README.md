# ARK examples

## `minimal_run/` — minimal end-to-end pipeline (issue #17)

A deterministic, minimal ARK flow so the repo can be *run*, not only inspected:

```
validate_run  ->  provenance validation  ->  report / evidence profile
```

### Inputs (committed)

| Path | Role |
|---|---|
| `minimal_run/kernels/kernel.{model,plan,events,schema,env}.json` | the five required kernel files, each payload-valid (content_hash + semver + payload) |
| `minimal_run/provenance/prov.json` | minimal PROV graph (1 entity generated by 1 activity, associated with 1 agent) |
| `minimal_run/expected/gate_report.json` | golden gate report (all fields fixed except `created_utc`) |
| `minimal_run/expected/evidence_profile.json` | golden evidence profile |

### Canonical command sequence

```sh
# One-shot orchestrator (validate_run -> provenance -> evidence profile):
python examples/run_pipeline.py --run examples/minimal_run

# ...which is equivalent to the individual stages:
python TOOLS/validate_run.py --run examples/minimal_run \
    --out examples/minimal_run/reports/gate_report.json
```

On Windows use `py` instead of `python`.

### Expected output

```
STATUS=ACCEPT hard=0 soft=0 warn=0 prov_neg=0
artifacts -> examples/minimal_run/reports/gate_report.json, examples/minimal_run/reports/evidence_profile.json
```

The written `reports/gate_report.json` matches `expected/gate_report.json` and
`reports/evidence_profile.json` matches `expected/evidence_profile.json` on every
field except `created_utc` (wall-clock timestamp).

### Deterministic replay

`reports/` is generated and git-ignored. Re-running the command is a pure replay:
outputs are byte-identical modulo the `created_utc` timestamp. The golden test
`tests/test_example_minimal_run.py` normalizes that single field and asserts
equality with the committed `expected/` artifacts.
